# Firefly-hyde 密码与安全检查（2026-10-11）

本次检查覆盖仓库源码、可见 Git 历史、公开构建产物、管理 API、CI 权限、依赖公告与编辑环境中本项目进程。它能检查已知模式、修复确认问题，不能证明没有未知漏洞、第三方包没有恶意行为，或 Cloudflare/GitHub 账号的实际授权正确。生产资源和真实 Secrets 没有在此环境中完成核验。

## 密码怎么填写

在 `firefly-hyde` 运行时 **Secret** `ADMIN_PASSWORD` 填写原始密码，长度 **3–10 字符**，不需要自行加密。Worker 自动用独立 `IP_HASH_SECRET` 计算 HMAC-SHA256 指纹，恒定时间比对；会话数据库只存指纹，不存原始密码。`IP_HASH_SECRET` 至少 32 字符，必须独立随机生成。密码或密钥改变后旧会话失效。本次指纹算法更新也会要求已有会话重新登录。

哈希不能让短密码免于在线猜测；尤其 3 位纯数字只有 1,000 种组合。建议在允许范围内使用 10 位随机字母、数字和符号，保留现有 IP/全站限流。Cloudflare Secret 的静态加密由平台管理，普通文本变量或 `PUBLIC_*`、`VITE_*` 不能代替 Secret。

## 数据与权限边界

- 管理 API 的文章、草稿、设置、评论邮箱、申请资料、媒体及备份都要求服务端登录；写操作继续验证同域 Origin 和 CSRF，响应不缓存。
- 公开 API 只返回公开评论字段、已经发布的友链/媒体以及 Turnstile **公开 Site Key**；邮箱、私密申请说明、环境密码和 token 不在公开响应中。健康接口会列出缺少的配置名称，提供名称不等于泄露其值。
- GitHub 发布 token 只需目标仓库 Contents 写、Checks 读、Metadata 读；Cloudflare 后台 token 只需版本/部署读取。代码不申请账号管理、账单或其他项目授权，也不能缩减一个被用户错误配置为过宽的 token。
- 发布操作会读取本项目原文、将明确发布的内容写入指定仓库，并核验官方 Check、完整 SHA、Worker tag 与生产清单；不是任意后台自动修改仓库。
- 邮箱和评论内容只在访客明确提交时进入 D1；IP 只用于带独立密钥的限流标识。免费模式没有邮件外发。不要把敏感信息写进准备公开发布的文章。
- 现有统计 ID、脚本地址为空，录屏/会话回放/出站追踪默认关闭。公开页面的外部图片、公开 API、字体或音乐来源仍可能获得访问者 IP/浏览器请求信息；这不是“完全没有对外请求”。后台页面不注入统计脚本，CSP 限制脚本和 API 连接为本站。

## 验证与剩余风险

后台 81 项测试、UI 40 项（含 DOM/XSS 测试）、旧网关 8 项、集成网关 5 项、发布清单 4 项、构建处理 6 项通过。类型、Astro 和 Biome 检查通过；兼容性测试确认升级后的 YAML CLI 可用，AI 工具默认拒绝运行。完整构建另外用假秘密检查公开产物不会包含运行时 Secret。

扫描没有发现真实私密凭据模式；历史 Twikoo 库中的两个 AWS 标识精确匹配 AWS 官方公开示例。扫描不展示凭据值，不会因为一个长随机字符串“看起来安全”而替用户证明其安全。大型二进制资源未逐一逆向审计，账号真实 Secrets、安装 App 授权、第三方服务端和生产域名尚未核验。

同域后台仍依赖博客端的 XSS 防护；有权发布 MDX/脚本的管理员具有代码发布能力。新增第三方脚本或允许恶意作者发布内容，会改变风险边界。3 位密码、过宽 token、账号被盗、未来供应链漏洞、免费额度耗尽和只在同一 D1 中保留备份，都是仍需注意的实际边界。JSON 备份没有图片字节，独立灾备需另存完整 D1 导出。
